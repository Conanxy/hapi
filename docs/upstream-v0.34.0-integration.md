   个人 MCP 桥接，并在服务声明支持时尽力调用 `session/close`。
2. DSH 恢复失败时沿用上游行为：提示并新建会话。Hub 中可见的旧聊天记录
   不代表新会话继承了旧模型上下文；旧版未保存原生 ID 的会话也无法按该 ID 恢复。
3. Android 保留 vivo 推送和图片压缩配置，兼容上游分享入口及主题设置；
   分享导入读取已保存的压缩设置。

5. Hub 保留个人会话排序字段及上游已读修订逻辑；从当前结构反向重建个人 v25
   结构的回归用例已执行至 v30，但不能替代真实历史数据库的升级验证。

## DSH 兼容性

上游 HAPI 的 v0.34.0 实现不传入 MCP，注释称其使用的 DSH ACP 组合会拒绝
非空 MCP 列表。另行查看 DSH 官方 `dsh-v0.2.1-rc.5` 源码，其 ACP 实现
接受客户端提供的 stdio MCP 配置，并声明 `resume` 与 `close` 能力。
两者说明适用的 DSH 版本或组合可能不同；本机 shell 中发现的 DSH 为
`0.1.5-rc.1`，实际 Runner 使用的版本和配置尚未核实。

使用隔离安装的 `0.2.1-rc.5` 进行了真实 DSH 测试：同一进程内，
活动会话不能重复恢复，调用 `session/close` 后可恢复同一个原生会话 ID。
另使用临时 Hub、临时数据库、真实 HAPI CLI 和本机模拟模型，验证了消息持久化、
CLI 退出后通过 `hapi resume` 恢复原生上下文，以及恢复前后调用 HAPI MCP
`skill_lookup`。测试禁用了 peer 工具，并使用独立的测试 skill。

本机安装的 DSH `0.1.5-rc.1` 也通过了隔离测试；其实际安装的
`@deepseek-ai/dsh-acp` 依赖为 `0.1.5-rc.2`。同一进程内关闭活动会话后，
可以恢复相同的原生会话 ID；另以真实 HAPI 启动器和本机模拟模型验证了
恢复前后的 `skill_lookup` 调用，以及恢复后的模型请求包含先前的用户消息。
这些测试使用模拟 HAPI session client，没有连接现有 Runner。

当前集成不会在 MCP 被拒绝时自动去掉 MCP 重试，因此不支持注入的服务可能
无法启动。实际 Runner 使用的 DSH 版本及配置尚未核实；其他 MCP 工具和
真实模型服务也未通过此次测试验证。

## 草稿夹图片兼容性

1. 自定义 `HAPI_SCRATCHLIST_ALLOWED_ATTACHMENT_MIMES` 只允许 PNG 而
   不允许 JPEG 时，个人图片预压缩可能将符合限制的 PNG 转成 JPEG，
   导致无法加入草稿夹。该问题在当前个人基线已存在。
2. Web 在聊天及草稿夹图片预处理前读取 Hub 附件限制；不允许 JPEG 或
   限制获取失败时保留原图。Android 和 iOS 草稿夹导入也按已知限制处理，
   限制获取失败时不转换为 JPEG，并在每次导入时重新读取限制。
   Hub 默认允许 JPEG；生产环境是否自定义该配置尚未核实。
3. 为避免格式转换，部分原图不会被压缩；原图超过大小限制时仍会被拒绝。
   限制未知时 Android 和 iOS 仍使用默认大小及格式预算做本地检查，最终由 Hub
   校验。之前已转成 JPEG 的旧草稿无法恢复原图，需要重新选择原图。
4. Web 使用模拟图片编码和 Hub 实际 MIME 判断逻辑测试，未进行浏览器真机
   图片编码验证。Android 和 iOS 新增原生导入测试并通过源码编译，
   尚未在设备或模拟器上运行。
