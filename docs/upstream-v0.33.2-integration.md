## 增量行为

| 改动 | 集成方式 |
|------|----------|
| 会话排序 | 采用上游最后一条用户消息时间排序，移除固定顺序开关，保留手动置顶；共享协议、REST/SSE、Web、iOS 和 Android 同步携带时间字段。 |

| Peer 投递 | CLI/MCP 支持 `queue` 与 `steer`；DSH 保留默认队列投递，不扩展为不受支持的 steering 目标。 |
| Android 设置 | 接入上游 `ChoiceDialog`，个人图片压缩数字选项委托同一控件；保留 vivo 推送入口和纯状态预览。 |
| 单附件控件 | 接入上游单附件隐藏拖柄的修改，保留个人附件恢复、压缩及草稿逻辑。 |
| v24 测试夹具 | 采用上游完整修正，保留删除依赖索引的语句及注释。 |
| 版本与打包 | CLI、锁文件、共享版本、Android 默认版本和 iOS 项目版本统一为个人版本；五个平台重新构建，不复用 v0.33.1 二进制。 |

## 发布检查点

源码和新构建产物已经完成本地验证，双语 README 暂时保留候选版标记，
避免把尚未上传的版本描述为已发布。npm 身份检查返回
`E401 / 401 Unauthorized`，恢复登录后方可继续上传。

不得改用旧的 v0.31.2 或 v0.33.1 二进制。五个平台包可查询后再发布主包，
最后确认全部六个包的版本及 `latest` 标签，然后更新 README 的发布状态。
服务器更新由用户自行执行现有运维脚本。
